How do I find exposed API keys and secrets in my codebase?

Run a free, local secrets scan — no code ever leaves your machine, and results come back in seconds.

CLI + Web upload14 secret typesSARIF for CIPlaceholder filtering
Short answer: Run webscan run secrets ./my-project. It scans every file for 14 classes of hard-coded credentials (AWS keys, Stripe keys, GitHub/GitLab tokens, private key blocks, DB connection strings, JWTs and more), redacts the evidence it shows you, and skips obvious placeholders so you only see real findings.

The command

pip install webscan-light
webscan run secrets ./my-project -f html -o secrets-report.html

Prefer the web UI? Zip your project folder and upload it at /tool/secrets — it's scanned in an isolated, size-limited sandbox and deleted immediately after. Nothing is written to the server's own disk.

What it actually detects

  • AWS access keys & secret keys
  • GitHub, GitLab, Google, Slack, Stripe, Twilio and SendGrid tokens
  • Private key blocks (RSA/EC/DSA/OpenSSH/PGP)
  • Database connection strings with embedded credentials (MySQL/Postgres/Mongo/Redis)
  • JWTs and generic high-entropy api_key = "..."-style assignments

Why this matters

A secret committed to source control is compromised the moment it's pushed — forks, CI logs, and local clones all carry it forward even after you delete the line. Combine this with a supply-chain scan to cover both halves of your dependency risk: what you wrote, and what you imported.

Frequently asked questions

What counts as a secret?
API keys, cloud credentials (AWS/GCP/Azure), database connection strings with embedded passwords, JWTs, private key blocks, webhook URLs, and generic high-entropy key = "..." patterns.
Does it scan git history, or just the working tree?
The built-in scanner checks the files currently on disk. If a secret was committed and later removed, it can still be recovered from git history — pair this with a history-aware tool like gitleaks for that case.
Will it flag placeholder values like <code>your-api-key-here</code>?
No — a placeholder filter specifically excludes example/test/dummy/placeholder-style values so you're not drowning in false positives.
Can I run this in CI?
Yes — webscan run secrets ./ -f sarif produces SARIF output that GitHub code scanning understands natively.
