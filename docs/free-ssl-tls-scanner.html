How do I check if my SSL/TLS configuration is actually secure?

Run a free scan of your certificate, protocol versions, and cipher suites — including hosts that aren't publicly reachable.

TLS 1.0–1.3 matrixCipher strengthInternal hosts OKPart of full scan
Short answer: Run webscan run ssl yourdomain.com. It inspects the certificate chain and expiry, probes which TLS versions (1.0–1.3) are still accepted, and flags weak cipher suites.

The command

webscan run ssl yourdomain.com -f html -o ssl-report.html

This check also runs automatically as part of the full website scan (webscan scan yourdomain.com), alongside security headers, cookie flags, and version-based CVE correlation.

What "good" looks like

CheckTarget
Protocol versionsTLS 1.2 and 1.3 only — TLS 1.0/1.1 and SSLv3 disabled
CertificateValid chain, not expired, correct hostname match
CiphersNo RC4, no export-grade, no NULL ciphers

Why self-hosted matters here specifically

Public SSL scanners can only reach public hosts. If the certificate you're worried about is on a staging server, an internal API gateway, or anything behind a VPN, a self-hosted scanner is the only way to check it without exposing it to the internet first.

Frequently asked questions

What does it actually check?
Certificate validity and chain, the full matrix of supported protocol versions (TLS 1.0 through 1.3), cipher strength, and common misconfigurations like expired certs or weak ciphers still being offered for compatibility.
Is this as thorough as Qualys SSL Labs?
It's lighter — SSL Labs does a far deeper protocol-level audit. What webscan-light adds is that it's self-hosted (useful for internal/non-public hosts SSL Labs can't reach) and runs as one check inside a broader scan, not a standalone one-off.
Can I scan an internal or staging host?
Yes — that's one of the main reasons to self-host: point it at anything your machine can reach, public or not.
